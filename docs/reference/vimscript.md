# Vimscript

rim runs a subset of legacy Vimscript that is being made identical to Neovim's, by porting its code (see Conformance). Code: `crates/rim/src/editor/script.rs` (variables, `:let`, `:unlet`, `:echo*`, `:execute`, `:call`) and `script/`: `cmdline.rs` (where a command ends: flags per command, `separate_nextcmd`, the commands that find their own end), `docmd.rs` (`do_cmdline`, `do_one_cmd`, `:source`, error headers), `cstack.rs` (`:if`/`:while`/`:for` and friends), `value.rs` (types, text of numbers), `expr.rs` (port of `eval.c`: `eval0`…`eval7`), `lval.rs` (port of `get_lval`, `set_var_lval`, `ex_let_vars`/`ex_let_one`, `get_name_len`, `eexe_mod_op`), `typval.rs` (`tv_get_*` conversions with their messages), `funcs.rs` (the table of builtin functions: name, arity, implementation, indexed by a `HashMap`; a new function is one `fn` and one row), `printf.rs`. Commands are entered at the `:` line; the expression register (`Ctrl+R =`) uses the same evaluator and sees the variables.

## Conformance with Neovim

Vimscript here must behave as Neovim's (v0.12.6, the version the goldens are recorded from); every doubt is settled by reading its C source (`ex_docmd.c`, `ex_cmds.lua`, `eval.c`, `eval/*.c`, `ex_eval.c`, `runtime.c`, `message.c`), never by memory. The tests are differential:

- `crates/rim/src/editor/script/cases/*.vim` hold scripts separated by `"---` lines; `*.golden` hold what Neovim printed for each (`:redir` output: every message starts on a new line), recorded by `python3 -I tools/vimscript_oracle.py` (needs `nvim`). The oracle sources each script with its own `-c`, since an error ends the rest of a command line and `silent!` changes how errors are reported; `{file}` stands for the script path; the `command line..script` part of an error header, present only because of the `-c`, is dropped.
- `script/golden.rs` runs each script through `Editor` (`Messages::redir` collects what is shown, as `:redir` does) and compares; the buffer starts empty, as Neovim's. `KNOWN` lists the cases that still differ, by number; a case that starts matching must be removed from it, and the list only shrinks. `RIM_GOLDEN_SHOW=1 cargo test -p rim -- <name>_cases_match` shows every difference, the known ones too.
- Files named `*.typed.vim` hold lines typed at the `:` prompt one after the other (`feedkeys()` in Neovim, `Editor::command` in rim): a typed line goes through `do_cmdline` differently from a sourced one (no `DOCMD_VERBOSE`, no source lines, no `E171`).
- `cases/args.vim`: 879 calls, each builtin with one argument of the wrong type at every position.
- `cases/execute.vim` (171): `execute()` with a command, a List of lines, the second argument (`''`, `'silent'`, `'silent!'`, anything else), the type errors, blocks and loops in a List, exceptions, nested calls, messages with and without `echon`, errors after a silent message. The blanks that `redir_write` pads to `msg_col` (also the ones `msg_advance` leaves for a `:let` listing under `:silent`) go to the redirection file while `execute()` captures, the text does not. Not covered: `:redir` around `execute()` (the oracle's own redirection), a List that loses the item it is about to read (Neovim reads freed memory), `:sleep` (rim has none).
- `cases/funcs.vim` ends with 36 cases of names made with `{expr}` (`exists('*{"F"}')`, `:call {"F"}()`, `:function {"G"}()`, `let g:{[1]}`). Found and fixed: a List or Dictionary in braces is written as `string()` does (and expanded again, so `{{}}` is `E15`), the error of the expression is shown also by `exists()`, a name made from braces keeps a `g:` (no function has it) and loses only `s:`, a new variable with an invalid name is `E461`. Left out: `:function {"g:G"}()` (Neovim compares pointers of two buffers for `E884`).
- `cases/append.vim` (98) and `cases/append.typed.vim` (21): `:append`, `:insert`, `:change` (`script/append.rs`, port of `ex_append`/`ex_change`): the lines after the command up to `.`, the text after `|`, ranges and `0`, `!` (autoindent is on in Neovim and rim, `!` turns it off, an indented `.` ends the text when autoindent has put that indent), empty buffer, inside blocks, loops (a loop whose condition is false parses the text lines in skip mode: `a{i}` is `E488`), functions and `:execute`/`execute()` (lines of the string itself), `E16`, `E493`, the marks `'[` and `']`. Typed at the prompt the command line opens again without the `:` and starts with the indent (`pending_append`, `AppendState`); Esc ends the text. The cursor goes to the last line added, at the column it wanted (Neovim's 'nostartofline'; also `:N`). Left out: `undo` after them (`undo.vim` covers the undo message) and `l{`-lines in a loop (rim has no `:list`).
- `cases/undoline.vim` (1104, all match): `U` (`nv_Undo`, `u_undoline`). The line is kept by `u_save` when one line is saved (`u_saveline`: the text, the cursor column when the cursor is on it), `U` swaps it with the line as it is (a step of its own, `'.` at column 0, the cursor takes the column kept and its column is kept in turn), so `UU` is the identity; `u_clearline` at `open_line` (`o`, `O`, Enter, `r<CR>`), `dd`, `2cc`, `:m`, `:t`, `:retab`, `:r`, `:e!`; `:s` keeps its line through its own `u_save_cursor` with column 0, `cc` through `op_delete`'s. `U` makes no redo: `.` repeats the command before. Left out of the corpus (found, not `U` bugs): `.` after a failing `Ctrl-A` (Neovim makes an empty step) and `r<CR>` repeated by `.` on an indented line.
- `cases/bufarg.vim` (43, all match) and `editor/bufarg.rs`: a buffer named by an argument, `tv_get_buf` (`undotree({buf})`, `E158`): a Number (0 is the alternate buffer), `''`, `'$'`, and a name through `buflist_findpat` (the four attempts with `^` and `$`, listed buffers first, `%` and `#`, `E93`/`E94` are not given because the callers have errors off) with `file_pat_to_reg_pat` (`*`, `?`, `{a,b}`, `\` escapes, `E219`/`E220`) and `find_buffer` (the full path). The Vim regexp is translated for the Rust `regex` (the subset a file pattern makes; `fileignorecase` is the platform's default: on for macOS and Windows).
- `cases/undolevels.vim` (165, all match): `'undolevels'` -1 to 3 with 2 to 9 changes, then `u`, `3u`, `9u`, `g-`, `:earlier`, `:later`, `:undo N`, a branch. A freed header lets go of its `Document` versions (`Editor::trim_history` at `u_sync`: the versions are those of the live headers and the current text, the common ancestor of them is kept with its subtree and everything is renumbered; `'undolevels'` below 0 keeps one).
- `cases/undo.vim` (712), `cases/undo2.vim` (520) and `cases/undo.typed.vim` (320, all match): Phase F step 4, undo like Neovim's `undo.c` (`editor/undo.rs`). A step (header) is made by the first `u_save*` call of a command and stays open until `u_sync`: a typed key read in Normal or Visual mode (`may_sync_undo`: not in Insert mode or a command line unless a cursor key moved, not for keys of `:normal`, a macro or `.`), `u`, `Ctrl-G u`, a buffer switch. So a `:source`d script, `:normal`, `:g` and a macro are ONE step; the cases sync with `feedkeys("\<Esc>", "xt")` (a typed key) between their commands. Every command calls the `u_save*` Neovim's does: `u_save_cursor` (`~`, `r`, Insert mode `stop_arrow`, Ctrl-A, `do_put` of a character register), `u_save(top, bot)` (`op_tilde`, `op_replace`, `op_shift`, block operators, `J`, `:sort` before it reads its arguments, `:retab` per line, `:m`/`:t`, `:r` before it opens the file, `:put`, `do_put` linewise/block, which also saves first when the register is empty (`E353`)), `u_savedel` (`dd`, `cc`'s other lines, `:d`; it deletes the marks of the lines, as `mark_adjust` does), the `o`/`O` empty save, `:append`/`:change`, and `do_sub`'s line by line sequence (`u_inssub` per line break, `u_save_cursor` once, `u_savesub`, `u_savedel`; `sub_undo` simulates the line counts and the cursor because the text changes in one go: `Document::plan_replace`). Same-line reuse over the last ten entries, `u_getbot`, `ML_EMPTY` (`UndoTree::empty`), `'undolevels'` (freed headers, `-1`, `0`: an undo of the same step again is a redo), and `u_undo_end`'s counts and `before`/`after #seq  T` match. The structure is Neovim's: headers linked `uh_next`/`uh_prev`/`uh_alt_next`/`uh_alt_prev`, `curhead`/`newhead`/`oldhead`, so `u`, `Ctrl-R`, `g-`, `g+`, `:undo N` (`E830`), `:undo!`, `:earlier`/`:later` (`N`, `Ns`, `Nm`, `Nh`, `Nd`, `Nf`: `undo_time` ported with its two rounds and `above`), `:undolist` (`ex_undolist`), `:undojoin` (`E790`), `changenr()` and `undotree()` follow it. `u_undoredo`: the entries are applied to a copy of the text to find the first line that differs (the saved lines are `Text` snapshots), the cursor goes to `uh_cursor` or to the first changed line (`beginline(BL_SOL | BL_FIX)` with the column wanted otherwise; the column wanted is not touched by `:undo`, `g-` or `:earlier`, but by `u` and `Ctrl-R`), `'[` and `']` are lines, marks `a`-`z` and the Visual selection come back from the header, `setpcmark()` first. The `:e!` reload is a step of its own (`'undoreload'`: up to 10000 lines). Neovim facts found: `:sort`, `ex_read` and `do_put` save before they know what they do; `d$`/`D` on an empty line saves nothing (`op_delete`'s "trying to delete in an empty line" check) while `x`/`dl` there make a step (`oap->empty`); `msgmore` gives way to a kept message (`keep_msg`: the undo message and `:s`'s "N substitutions" are kept until another message or a redraw); `KeyTyped` is the last key read (`Editor::key_typed`); `:s` sets the jump mark at the first match, before the text changes; a linewise `d`/`<`/`>` starts at the wanted column and `cc` at the first non-blank (`nv_lineop`), which is what `uh_cursor` holds; `:` does not take the column wanted (`ex_copy` and the like read the old one) and the keys of `feedkeys()` are no `:normal` (no update at the end); a put always sets the redo (`prep_redo_cmd` before `do_put`); `J` adds no space after a Tab or a space or before `)`; `~` at the end of a line ends `']` one char before the last. Ports on the way: failing motions in Visual mode flush the typeahead, Insert `Ctrl-W`/`Ctrl-U` stop where Insert began, and the golden harness has no hit-enter prompt (`Editor::headless`, as headless Neovim: a hit-enter prompt waits for nothing). The messages are compared with the age replaced (`golden.rs` replaces "N seconds ago" on both sides; `undo.typed` also ignores blank lines: a message given by a typed key inside a typed command line starts a line of its own in Neovim). `undo.vim` prints `execute('undo')`, `execute('redo')` and `execute('normal! 3u')`; `undo2.vim` prints text, cursor, `changenr()` and the lines of `'[` `']` after every step of a random path through the tree (changes, `u`, `Ctrl-R`, `g-`, `g+`, `:undo N`, `:undo!`, `:earlier`, `:later`, `:undolist`, `:undojoin`, `'undolevels'`), the generators were scratch scripts and the files are plain now. Time based `:earlier 10s` and the `f` form are Rust tests (`undo_time_travel_by_time_matches_neovim` has values recorded from Neovim with sleeps; the headers' times are set by hand); the `f` cases need `:w`, whose message differs.

- `cases/linecmd.vim` (846): Phase F step 1, the line commands `:d`, `:y`, `:m`, `:t`/`:co`, `:>`/`:<`, `:j`, `:p`, `:#`/`:nu`, `:l`, `:=`, `:k`/`:mark` with every kind of range, argument, register, count and flag, the `report` messages, `:dl`/`:dp`, the registers after them and a few Normal mode deletes. - `cases/limits.vim` (592), `cases/marks.vim` (621), `cases/motions.vim` (1232), `cases/fmarks.vim` (168) and `cases/putdot.typed.vim` (56): what `linecmd.vim` first left out. `:put` (`ex_put` and the linewise branch of `do_put`: `:put`, `:put!`, `:0put`, a register of any kind (a character or block register is put as lines), `:put =expr` (the rest of the line is the expression, a List is a line per item), `:put _` (an empty line), the registers `%`, `#`, `/`, `:` (the last typed command line) with their errors `E32`, `E23`, `E35`, `E30`, `E353`, `:put .` (the empty line, then `i`, the text inserted last and Esc are typed when the command line is done, then `g'[`: `scripts.stuffed`, `run_stuffed`; `E29` when nothing was inserted), `N more lines`); the marks of `:k`/`:mark` and `m` (`a`-`z`, `A`-`Z`, `0`-`9`, `'`, `` ` ``, `\"`, `[`, `]`, `<`, `>`, `E191` for the rest); file marks belong to the session (`file_mark_owner`: the mark is in the buffer that set it, `'A` switches to it, `line(\"'A\")` is its line and `col()` 0 from another buffer, a mark inside deleted lines stays on the line that takes their place, in its column: `ONE_ADJUST_NODEL`); `use_reg_one` (`n`, `N`, `%`, `(`, `)`, `{`, `}` send a delete inside a line to `\"1` too, `\"-` still gets it). `'[`, `']` and `'.` after every command that changes text, as its C code sets them (`changemarks.rs`: `op_delete`, `op_yank`, `op_tilde`, `op_shift`, `do_join`, `do_put`, `do_move`, `ex_copy`, `do_sub`, `do_sort`, the Insert mode (`Insstart`, a run of typed chars is one change), `nv_replace`, `n_swapchar`, `:append`); a mark may lie past the end of its line or of the text (`dd` on the last line): `marks_beyond`, good while the text keeps its length. - `cases/tabs.vim` (420): the Tab model in screen cells. A Tab takes the cells up to the next multiple of `tabstop` (`tabstop_padding`), the virtual column runs on over the whole line also with `wrap`, and a wide char that would start in the last cell of a row takes that cell as a filler (`charsize_fast_impl`, `in_win_border`; the golden harness sets the window width to 80 as headless Neovim's). Covered: the new builtin `virtcol()` (port of `f_virtcol`: `getvvcol` start and end, the `[start, end]` form, positions `.`, `$`, `[lnum, col]`) at every byte column of lines with Tabs, wide chars and combining marks for `tabstop` 1, 2, 3, 4, 8, and of lines of 80 cells and more whose Tabs and wide chars meet the window edge; the cursor after `0`, `$`, `l`, `w`, `e`, `b`, `f<Tab>`, `t`, `;`, `h`, `N|`, `gj` and `gk` on lines with Tabs; `>>`, `<<`, `:>`, `:<` on mixed indents (a Tab in an indent goes to the next stop, not `tabstop` cells on).

## Values

| Type | `type()` | Notes |
|---|---|---|
| Number | 0 | `i64`, wrapping; `1/0` is the largest number, `0/0` the smallest, `x % 0` is 0 |
| String | 1 | a number by its first digits |
| List | 3 | `[1, 2]`, shared **by reference** |
| Dictionary | 4 | `{'a': 1}`, `#{a: 1}`, shared by reference; keys are strings; iteration order is a `HashMap`'s, printing sorts (see Differences) |
| Float | 5 | |
| Bool | 6 | `v:true`, `v:false`; numbers when used as one |
| None | 7 | `v:null` |

`let b = a` makes two names of one List or Dictionary; `copy()` is shallow, `deepcopy()` follows references once (a cycle copies as a cycle; `deepcopy(x, 1)` gives `E698` on one). Lists and Dictionaries are `dumpster::unsync::Gc` values: a cycle is freed by the cycle collector (`garbagecollect()` forces a pass). A cycle prints as `[...]` / `{...}`.

Coercions follow vim: String to Number by prefix, Float to Number is `E805`, List `E745`/`E730`, Dictionary `E728`/`E731`.

## Expressions

Operators: `? :`, `||`, `&&`, `== != < <= > >= =~ !~` (each with `#` or `?`), `is isnot` (identity of Lists and Dictionaries, same type and value for the rest; also `is#`, `is?`), `+ - . ..`, `* / %`, `! - +`, indexing `x[i]`, `x[a:b]`, member `d.key`, method call `x->name(args)` (the value becomes the first argument), `x == y` on Lists and Dictionaries compares items.

- `d.key` is a member access when the dot has no blank around it and the name is not called; with a left side that is not a Dictionary it is the concatenation with the variable `key` (`'a'.k`). With blanks, or before `(`, it is a concatenation.
- `[` after a blank still subscripts (`l [1]`), as in legacy vim; `:echo 'a' ([1])` to print two things.
- Names: `x` and `g:x` (global), `b:x` (buffer), `w:x` (window), `v:x` (rim's table in `script/vimvars.rs`: `true`, `false`, `null`, `count`, `version`, `progname`, ...; see Differences), `&opt` / `&l:opt` / `&g:opt` (one value per option: the three are the same), `@r`, `$ENV`.

## Scripts and command lines

A command line typed at `:`, a file read by `:source` and the init file go through the same code, a port of Neovim's.

- **`:so[urce] {file}`**: `~`, `~user`, `$VAR` and `${VAR}` are expanded as `expand_env_esc` does (`~user` through `getpwnam`; an unset or empty `$VAR` is removed, an unset or empty `${VAR}` and a `~user` that does not exist stay as written); `E484: Can't open file` names the expanded file, when it cannot be read; a directory is refused. `:[range]source` without a file runs the lines of the buffer (named as the buffer's file, or `:source buffer=N`). A range and a file together are `E481`. `:source!` (Normal mode commands) is not supported. Nesting stops at 200 levels (`E169`, `cmdline_call_depth`).
- **The file commands** (`:e`, `:sp`, `:vs`, `:r`, `:w file`, `:sav`, `:wq file`, `:x file`): the name is expanded as `expand_filename` does (`~`, `~user` through `getpwnam`, `$VAR`/`${VAR}` with `expand_env_esc`, a backslash keeping the char after it as written). `:e`/`:sp` also run Neovim's wildcard expansion, so a `~user` that does not exist says `E79: Cannot expand wildcards` — a plain message after a blank line, the command does nothing — where `:r`/`:w`/`:sav` take such a name as written; `:e` of the file the buffer already holds reads it again (see [rim.md](rim.md)).
- **The init file** `$XDG_CONFIG_HOME/rim/init` (or `~/.config/rim/init`) is sourced at startup: every command of the editor works in it.
- **Lines**: `getsourceline`: a line whose first non-blank is `\` continues the one before; `"\ ` lines in between are dropped; a newline escaped by an odd number of `Ctrl-V` goes on to the next line. A `\r` before the newline stays (as on Unix).
- **Where a command ends** (`do_one_cmd`): by the flags of the command in `ex_cmds.lua`. Commands with `TRLBAR` end at the first `|`, `"` (unless `NOTRLCOM`) or newline that is not escaped by a backslash (which goes); `Ctrl-V` takes the next char; trailing blanks go (`separate_nextcmd`). `:let`, `:unlet`, `:echo*`, `:execute`, `:call`, `:if`, `:elseif`, `:while`, `:for`, `:s`, `:&`, `:~`, `:sort`, `:syntax` and `:=` find their own end, as their handlers do (`check_nextcmd` after what they parse): after `:echo`/`:execute` a `"` starts the next string, after `:let`/`:if`/`:call` it starts a comment; `:s` takes `|` in the pattern and replacement; `:normal` and `:global` take the rest of the line (`:g` stops at a newline). A range alone goes to the line; with `|` after it (`:3|`) shows it. Command names are resolved as `find_ex_command` does: the first command of Neovim's table (`script/exnames.rs`, the order of `ex_cmds.lua`) the typed name is a prefix of; one rim does not have is `E492`. Modifiers are parsed as `parse_command_modifiers` does (after the range, `:silent`, `:silent!`, `:unsilent`, `:vertical`, `:keepjumps`…): `:silent` stops messages from being shown (a `:redir` still gets them), `:silent!` also hides errors, writes them to a redirection and does not end the line, `:unsilent` undoes it, `:vertical` applies to `:split`/`:new`/`:resize`; the others (`keepjumps`, `keeppatterns`, `lockmarks`, `noautocmd`, `topleft`, `tab`, `verbose`, `hide`, …) are accepted and have no effect; `:filter` is not supported. A modifier after a range is a command (`E481`).
- **After an error**: nothing else on the line runs, and in a block the rest of the block is skipped until it ends (`did_emsg`, reset when a line is read outside a block). Errors are `E481` (range not allowed), `E477` (`!` not allowed), `E471` (argument required), `E488` (trailing characters, after the register, count and flags a command takes), `E939`. Inside an `:if` that is not taken, only the commands that handle `|` themselves and the block commands run (`skip_cmd`); the others are dropped with the rest of their line.
- **Exceptions** (`script/exceptions.rs`, `ex_eval.c`): `:try`/`:catch [/pat/]`/`:finally`/`:endtry`/`:throw`; errors under a try become `Vim(cmd):E...` exceptions (the message is not shown, `v:errmsg` not set); pending `:break`/`:continue`/`:return`/`:finish` and exceptions go through `:finally`; `v:exception`, `v:throwpoint` (not `v:stacktrace`); uncaught: `E605: Exception not caught`; `E600`–`E608`, `E471`, `E654`. `abort` functions and `aborting()` stop expression evaluation after a thrown call.
- **Blocks and loops**: `:if`/`:elseif`/`:else`/`:endif`, `:while`/`:endwhile`, `:for {var} in {String or List}`/`:endfor` (`{var}` may be `[a, b; rest]`), `:break`, `:continue`, `:finish`, with a stack of 50 as `cstack_T` (`E579`, `E585`). A loop runs again by re-reading the stored lines, as vim does; `:for` keeps a pointer to the next item. Messages: `E580`–`E584`, `E586`–`E588`, `E732`, `E733`, `E690`, and at the end of a sourced file `E170`/`E171` (not for a typed line).
- **`s:`**: variables of the script file (or buffer), found again when it is sourced again.
- **Errors in a script** are shown as `Error in {file}:` (the chain `a[3]..b` for a file sourced from another), then `line {N}:`, then the message, the first two only when they changed since the last error (`last_sourcing_name`; a dismissed hit-enter prompt starts over). Errors found by `do_one_cmd` in a sourced file (or `:execute`) end with `: {command line}`.
- **`:execute`** runs its text as a command line with the current line source: in a sourced file, a block it opens goes on in the following lines, and `:execute 'finish'` finishes the file.
- **Here documents**: `:let x =<< [trim] [eval] MARKER` (port of `heredoc_get` and `eval_all_expr_in_str`, `script/heredoc.rs`): the lines come from the file being sourced without joining `\` lines, from the lines a `:while`/`:for` stored (`get_loop_line`: a loop replays them), from the argument itself when it holds newlines (`:execute "let x =<< END\nl1\nEND"`), or, for `:execute 'let x =<< END'`, from the caller's reader. `trim` takes off the indent of the first line and of the `:let` line, `eval` replaces `{expr}` (`{{`/`}}` are braces). In an inactive `:if` block the lines are read and dropped. Errors: `E172`, `E221`, `E488`, `E990`, `E991`, `E1278`, `E1279`. Typed at the prompt, the command line opens again without the `:` for each line (not kept in the history) up to the marker; Esc or Ctrl-C ends it as a missing end marker (`E990`) and the lines so far are assigned, as in Neovim; a command line that does not come from the prompt (`Editor::command`) gives `E991`. A carriage return is not white space: `let x = 1^M` is `E488`, and the marker of a file with CR LF lines includes it.
- **`:function`** (`script/userfunc.rs`, port of `ex_function`, `get_function_body`, `trans_function_name`, `list_one_function`, `ex_delfunction`): `:function[!] Name({args}) [range] [abort] [dict] [closure]` reads the body up to its `:endfunction` (nested `:function`, here documents, `:append`/`:insert`/`:change` text and `:lua <<` and the like are skipped over as Neovim does; a `\` continuation line is kept as one line followed by a hole, so that the line numbers hold); default values (`a = 1`), `...`, `E122` (redefinition: allowed with `!` and by sourcing the same script again), `E124`, `E125`, `E126`, `E127`, `E128` (a name that starts with a lower case letter), `E129`, `E130`, `E131`, `E193`, `E475`, `E746` (an autoload name must match the file), `E853`, `E884`, `E989`, `E1058`, `E1068`, `E1145`; `s:Name` and `<SID>Name` become `<SNR>{id}_Name`. `:function` lists them sorted by name (Neovim: hash order), `:function Name` shows the definition with line numbers (tabs are spaces to 'tabstop'), `:function! Name` as it was typed, `:function /pat/` those that match (Rust regex). Typed at the prompt the body is typed next, line by line, as for a here document; the name is checked first, `E122` before the body. In an inactive `:if` block the body is read and dropped. Not yet: Dictionary functions (`function d.f()`), closures, a variable holding a Funcref as a name (`E718` instead), `:defer`, the profile and verbose parts of the listing.
- **Calling a function** (`script/userfunc.rs`, port of `call_user_func`, `call_func`, `get_func_line`, `func_has_ended`, `ex_return`, `ex_call`): in an expression (`F(1)`, `s:F()`, `<SID>F()`, `<SNR>1_F()`, `g:F()`, `x->F()`) and with `:call`; `E117`, `E118`, `E119`, `E120`, `E132` (`maxfuncdepth` 100), `E133`, `E168` (`:finish`), `E725`. The body runs through `do_cmdline` reading its lines (`ReaderBase::Func`); an error ends a function with `abort` and returns -1, any other goes on with the next command (`did_emsg` is reset after each); `:return [expr]` ends it (value 0 without), also from a loop. `a:` has the named arguments, `a:0`, `a:000`, `a:1`..., `a:firstline` and `a:lastline` (the range of the `:call`, the cursor line for a call in an expression; a `range` function is called once for the whole range), is read-only (`E46`, `E461` for a new name) and has no `unlet` (`E795`); `l:` is the local variables, and a name with no scope written is one of them inside a function (`g:` reaches the global one); `l:` lists them. Errors name the call stack as `Error in {file}[22]..function Outer[1]..Inner:`. A failed `:call` drops the rest of its line (`| echo`), an error inside the function does not. `v:errmsg` gets every error, shown or not. `exists('*F')` knows user functions. - **Funcrefs and partials** (`Value::Func`, `Value::Partial`; `common_function`, `f_call`, `func_equal`, `call_value` in `script/userfunc.rs`): `function(name [, args] [, dict])` gives a Funcref (`type()` 2), or a partial when arguments or a Dictionary are bound; `funcref()` holds the function itself (`E700` for a builtin) and keeps working after a redefinition (`E933` after `:delfunction`); `call(func, args [, dict])`; `get(F, 'name'|'func'|'dict'|'args'|'arity')`. A Funcref is called as `F()`, `l[0]()`, `d.f()`, `function('f')()`, `x->F()`, `call()`, and as the callback of `sort()`, `uniq()`, `map()`, `filter()`, `foreach()` (the key and the value are its arguments); a variable that holds one is called through it and an unknown function behind it is `E1085`. `echo F` shows the name, `string(F)` and the items of a List `function('name')` (a `funcref()` of a global function `function('g:Name')`), a partial `function('name', [args], {dict})`. `==` compares function, arguments and Dictionary, `is` the same partial; `E694` for other operators, `E703`/`E729`/`E891` when one is used as a Number, String or Float. A variable that gets one must start with a capital (`E704`; `w:`/`b:`/`s:`/`t:` are free) and cannot hide a function (`E705`); `:let` lists it as `*name()`. `self` is `l:self` of a `dict` function that is called with a Dictionary. Not yet: `json_encode()` of one.
- **Dictionary functions**: `d.f(args)` calls the Funcref in the item with `d` as `self` (`l:self` of a function with the `dict` flag; `E725` without a Dictionary); a `dict` function taken out of a Dictionary (`let F = d.f`, `{'f': d.f}`, `sort(l, d.f)`) is bound to it (`pt_auto`, `set_selfdict`/`make_partial`), unless it was bound explicitly (`function('f', d)`). `:function d.f()` and `:function! d.f()` (a key of a Dictionary, also `g:d.f`, `d.a.f`) define a function with the `dict` flag, named by a number (`function('1')`), and put it in the item; `E717` when the item exists without `!`, `E716` for a missing key without parentheses, `E718` for an item that is not a Funcref, `E862` for `g:` itself. `:delfunction d.f` removes the item. `:call d.f()` and `:call l[0]()` call the item. A Dictionary function stays defined while something might refer to it (`// shortcut:` in `userfunc.rs`: nothing is freed).
- **Lambdas and closures** (`get_lambda_tv`, `Scoped`, `check_vars` in `script/userfunc.rs`): `{a, b -> expr}` is a function `<lambda>N` (listed by `:function <name>` or `:function F` with `F` holding it, hidden from `:function`), a partial; its named arguments are local variables (`a:1`, `a:000` and `a:name` exist only when the text has `a:`), extra arguments are accepted, a missing one is `E119`. `base->{a -> expr}(args)` calls it with the base first. A lambda made in a function that uses a local variable or argument (`check_vars` while the body is skipped) is a closure: it keeps the variables of that call (and of the calls it was in), looks them up after its own, and an assignment to one changes it; `function! F() closure` inside a function does the same (`E932` at the top level). A lambda that fails gives -1 when nothing of its expression was evaluated and 0 after a term was. `E451` for a missing `}`, no `E15` after a more specific error (`eval1_emsg`).

- **Not done**: reading further lines for `:append`; a typed `:if` does not ask for more lines; `:filter`; `:source!`.

## Functions

Numbers and math: `abs round floor ceil sqrt pow exp log log10 sin cos tan atan atan2 float2nr str2nr str2float`. Strings: `string len strlen strchars strcharlen toupper tolower repeat printf substitute matchstr trim split strpart stridx strridx char2nr nr2char escape tr`. Text: `getreg getline line col`. Lists and Dictionaries: `type empty len get index min max copy deepcopy join sort reverse add remove insert extend count uniq flatten keys values items has_key range filter map mapnew foreach`. Others: `eval exists has garbagecollect`.

`add`, `insert`, `extend`, `remove`, `sort`, `reverse`, `uniq`, `flatten` change the List in place and return it (`remove` returns what it took out). `exists()` takes a variable name, `&option`, `$ENV`, `*function` (builtins), `:command` (the ones rim has), `##event` (the event names of `auevents.lua`; `#event` is always 0: there are no autocommands) or `@r`. `has()` knows `float`, `eval`, `rim`, `unix`, the system names (`mac`, `linux`...), `multi_byte`, `num64` and `vim_starting` (true until the init file and the command line files are loaded, `Editor::finish_start`).

Comparing, joining and flattening nested Lists and Dictionaries stops at 100 levels with `E724`; the same List twice is equal at once.

## Differences from vim

- **Options**: rim's defaults are its own (`tabstop=4`, `number`, `relativenumber`, `cursorline`, `expandtab` on...), not Neovim's; `:set` is a port of `do_set` (prefixes `no`/`inv`, `!`, `&`, `?`, `+=`/`-=`/`^=`, E518, E521, E487, E474, E488, the layout of a query: two blanks, `no` in front of a flag that is off) for the options rim has. There is no global/local distinction: `&g:ts` and `&l:ts` are the one value. `'report'` (default 2) decides the "N fewer lines", "N lines yanked", "N substitutions on N lines" messages as in Neovim.
- **`:const` and the reference count**: C locks a List or Dictionary only when its `refcount` is 1 (`tv_item_lock(.., check_refcount)`), so `let a = [1] | const b = a` locks `b` but not the List. rim has no refcount field: `Value::is_shared` is `Gc::ref_count > 1`, asked of the value where it is kept before any clone is made (the caller's value in `set_var_lval`, each child in `item_lock_in`). A value unpacked from a List (`const [a, b] = ..`) is held by the List too, so it stays unlocked, as in C (`copy = true`). Checked against Neovim by `const.vim` and `const.typed.vim`.
- Locks: `:lockvar`, `:unlockvar`, `:const` (`E995`, `E996`, only a List or Dictionary that nothing else holds is locked), `islocked()` and the checks of `:let`, `:unlet` and the builtins are ported (`E741`, `E742`, `E46`, `E795`, `E1122`, `E940`, `E743`). `v:event` and `v:completed_item` are fixed Dictionaries, but rim fills neither. `flatten()` of a locked List crashes Neovim when called with `:call` (rim gives `E741`), and `extendnew()`/`flattennew()` are missing builtins.
- `:let` with no argument lists `g:`, `b:`, `w:`, `t:`, `s:` (in a sourced script) and `v:`, as `list_hashtable_vars` does, each sorted by name. `b:changedtick` is not listed (rim keeps no change counter). The `v:` table is rim's: `v:progname` is `rim`, `v:progpath`, `v:argv` and `v:starttime` are rim's process, `v:lang`, `v:ctype`, `v:collate` and `v:lc_time` come from `LC_ALL`, the category and `LANG` as `setlocale` reads them (`C` without any); `v:servername` is empty (rim has no server) and `v:echospace` is 0; and a `v:` String that is empty is taken for a NULL one and not listed. The golden case compares the other scopes only; a unit test covers the order.
- `:!` and the other commands rim does not have give E492; a modifier given a range is E481 as in Neovim.
- A `:for` over a List follows what the loop body does to it as Neovim's watcher does: `remove()`, `insert()`, `extend()`, `filter()`, `uniq()`, `flatten()`, `:unlet`, and `sort()`/`reverse()` (the next item stays the same item).
- `printf('%p')` reads its argument as a number, and `printf('%c', n)` above 127 is U+FFFD.
- **Strings are always valid UTF-8** (deliberate, permanent): Neovim's are byte strings. Where Neovim makes bytes that are not UTF-8, rim has the closest valid text: `"\x80"`, `"\xc3"` and lone surrogates are U+FFFD, `"\200"` is U+0080, a `[i:j]` or `strpart()` cut inside a multibyte char gives U+FFFD, and a key name Neovim stores as `K_SPECIAL` bytes (`"\<BS>"`, `"\<Del>"`, `"\<F1>"`, `"\<M-a>"`, `"\<C-@>"`, `"\<C-Space>"`, `"\<S-Tab>"`) stays as typed. `printf()` is a port of `vim_vsnprintf_typval` (all conversions, flags, widths, precisions, `*`, positional `%1$s`, its error messages): `%c` of a number above 127 is U+FFFD (Neovim writes one byte) and `%.Ns` cutting inside a multibyte char gives U+FFFD. `len()` and the like count the bytes of the UTF-8 text.
- Ranges (`script/range.rs`) follow `parse_cmd_address`; a backwards range typed at the prompt asks "Backwards range given, OK to swap (y/n)?" (`ask_yesno`: `y` runs the command, `n`, Esc and `Ctrl+C` drop it with the rest of its line, other keys wait; `:silent` swaps, a sourced or `:execute`d one is `E493`, `:global` does not swap); inside a block, `:normal` or `:execute` rim swaps without asking; not done: the warnings of a search that wraps, the `:filter`, and addresses of tab pages, arguments and the quickfix list. A search address does not change the offset that `n` repeats, as Neovim's `do_search` does.
- **Regular expressions are Rust's** (deliberate, permanent, user decision): `:s`, `:g`, `/`, `split()`, `matchstr()`, `substitute()`, `=~` use the engine rim already has, not Vim's: no `\(\)`, `\+`, `\|`, `\{}`, `\d`-style classes as Vim spells them, the replacement uses `$1` where Vim has `\1`. What is around the pattern (the delimiters, flags and count of `:s`, `keepempty` of `split()`, the default pattern of `split()`) is Neovim's and is tested; the golden cases only use patterns that mean the same in both.
- **Dictionary and variable-scope order is arbitrary** (deliberate, permanent): they are Rust `HashMap`s, so `keys()`, `values()`, `items()`, `map()`… visit them in an order that can change between runs; Neovim's is the one of its hash table and is not matched. Printing (`:echo`, `string()`, the `:let` listing) sorts by key. Scripts and tests wrap `keys()` and the like in `sort()`; the golden cases do, and a case whose first line is `"unordered` is compared with its output lines sorted.
- Window ids start at 1000, as Neovim's (`line('.', {winid})`, `col()`); there is no `win_getid()` yet.
- `:let $ENV` is the one `unsafe` of the language (`set_env`, `std::env::set_var`): the background save thread never reads the environment.
- `:let &opt = value` takes the value whole, as vim does; only a flag option goes through `:set`.
- The messages of rim's own ex commands and options (`:set`, `:d`, `:s`, marks, ranges…) mostly lack the `E` numbers and exact texts of Neovim (`Unknown option` is `E518`, `Invalid range` is `E16`…), and `:s` uses Rust's regex syntax; they are not part of the language and are Phase F.
- `sort()` takes `{func}` as a function name (a String) only: there are no Funcrefs.
