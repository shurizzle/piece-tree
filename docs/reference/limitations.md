# Limitations and roadmap

## Library

| Limit | Impact | Upgrade path |
|---|---|---|
| In-place edits need an unshared version | `Text::insert_mut` / `delete_mut` and `Document` inside a group update nodes in place (typing 13 ns per key, paste 330 ns, backspace 20 ns); when each edit must stay a version (`Document` without a group, or a clone per edit) the path is copied: 50-60 ns per key, ~610 ns per paste | Nothing to do: a kept version needs its own path. Ranges that span pieces, and whole-piece deletes, are always persistent (`split` + `join2`) |
| Pieces still multiply under scattered edits | Extension only helps contiguous typing; random edits still add pieces (~3000 after 2000 random edits) until `Text::compact`/`Document::compact` runs (the editor does it on idle past `compactat` pieces) | Compaction is explicit: the library never compacts on its own |
| Chunks stay alive while referenced | A chunk whose text is mostly deleted is kept whole by the remaining pieces, and by every version in the undo history, also after `compact` | `Document::drop_history_before` frees what only older versions use |
| `memory_bytes` is approximate | Counts chunk buffers at capacity and nodes, not allocator overhead or `Arc` headers; shared structure is counted in every version | Good enough for `:stats`; exact accounting would need allocator hooks |
| Add chunk allocated in full | Up to 64 KiB bytes + 64 KiB newline slots reserved per add chunk (untouched pages are usually not committed by the OS) | Smaller maximum, or a separate growable newline area |
| Mixed line endings normalized to one | Saving rewrites the other endings | Track original endings per line if fidelity is ever required |
| Chunk ≤ 4 GiB (`u32`) | Files over 4 GiB cannot load (one exact chunk) | Split large loads into several exact chunks |
| `rfind_before` worst case O(n log n) | Backward search with few matches and none after the cursor rescans doubling windows to the start | A reverse regex engine, or an index of match starts |
| Char conversions scan | Per-line ones are O(line length), global ones (`char_count`, `offset_to_char`, `char_to_offset`) O(n), measured 0.008-0.034 ns/B (0.4-1.7 ms for 50 MB, SIMD counting from `str_indices`); on a 1 MB single line every column conversion scans the line | A char index per sealed chunk built lazily on the first char query (see D15) |
| Newline scan is SIMD only on aarch64 and x86_64 | NEON and SSE2 `mask64` (~0.1 ns/B on the M1, ~0.26 on an i5-8365U, Rust sources); every other architecture (wasm32, 32-bit x86, loongarch64, s390x, riscv64, powerpc64) uses the portable SWAR mask (~0.13 ns/B on the M1). On x86_64, AVX2 and SSE4.2 were tried and lost; AVX-512BW is not worth trying | One `mask64` per architecture where it beats SWAR, in the order and with the `std::arch` status and test needs listed in D16 (wasm32 simd128 and 32-bit x86 first: stable intrinsics), or `std::simd` once stable; same A/B acceptance as D16 |
| History is never freed | Every version (and the chunks it references) lives until the `Document` is dropped | Drop versions older than a seq or a time |
| Atomic refcount traffic | Path copies clone sibling and chunk `Arc`s; drop of old versions dominates benchmarks that discard every version | Non-atomic `Rc` would lose `Send + Sync` snapshots; batch edits (one version per group) if needed |
| Recursion in `join`/`split` | Depth O(log n), not an issue in practice | — |

## Editor

| Limit | Impact | Upgrade path |
|---|---|---|
| Every option is buffer-local (`shortcut:` in `editor/buffers.rs`) | `:set` changes the current buffer only; a new buffer copies the current one's options; `wrap`/`number` cannot differ between two windows on one buffer | Split window-local options into `Window` |
| The last buffer cannot be deleted (`shortcut:` in `editor/buffers.rs`) | `:bd` on the only buffer reports `Cannot delete the last buffer` | An unnamed empty buffer |
| Huge lines are not free (`editor/layout.rs`, `editor/render.rs`, `editor/search.rs`) | Typing, motions, objects and scrolling in a line of millions of chars cost the window around the cursor (see `rim.md`, Huge lines). Still O(line): the first jump deep into a line (2.1 M chars of CJK: about 5 ms to build its cluster index and lay out its prefix once, ASCII 1 ms), `gk`/`k` into a huge line above (it is laid out whole, then kept), a failed `ci(`-style search (scans back to the text start), sentence objects, `yy`/`p`, and a text change on a visible huge line with `hlsearch` (the regex runs from the line start so matches stay exactly vim's: 100 000 matches about 7 ms, none about 0.2 ms) | Checkpoints of the row layout and of the match state per line |
| Save via temp file + rename | Permissions are copied and symlinks followed, but hard links are broken, owner is kept only when allowed (root or same user), ACLs and xattrs are lost | Write in place after a backup |
| `:highlight` is a subset of vim's (`editor/highlight.rs`) | Color names are the 16 of vim plus a few X11 ones (`NAMES`, not all of rgb.txt), no `fg`/`bg` as a color, `guisp` is checked but not drawn, no `font`, `blend`, `start`/`stop`; `:hi` lists only the user's groups; `:set bg=` keeps the user's groups (vim reloads the colorscheme); with `termguicolors` a missing `gui*` key falls back to its `cterm*` value, which vim does not; groups are global, not per buffer | The rest of rgb.txt, undercurl colors and a pager for the listing on demand |
| Vim subset only | No vim regex syntax (Rust `regex` only), uppercase (file) marks, `-` small-delete register, block `O`, multi-cursor | Add on demand |
| Tag objects scan the whole text (`shortcut:` in `editor/objects.rs`) | `it`/`at` slice and scan the text on every use | Scan outward from the cursor |
| The system clipboard is read only through OSC 52 | `"+p`, `Ctrl+R +` and `@+` send an OSC 52 query and wait up to 500 ms for the answer; a terminal that does not answer it (or has clipboard reads disabled) gets `Clipboard read failed`, with no fallback | None planned: terminals without OSC 52 reads are unsupported |
| `:p` shows one line (`shortcut:` in `editor/ex.rs`) | `:p` and `:g/pat/` show only the last line printed (one message row) | A message pager |
| Ex corner cases (`shortcut:` in `editor/ex.rs`, `editor.rs`) | Marks on lines moved by `:m` stay where the lines were; the `c` flag of `:s` is refused under `:g`/`:normal`; `:r` copies the file into the text | Marks that follow lines; a confirm loop that waits; `Text::append_text` |
| Marks in removed text | A mark inside removed text moves to the removal's start, and undoing the removal does not bring it back inside (vim keeps the line) | Keep a line-relative position for marks in removed lines |
| A tab cut by a block edge is taken whole (`shortcut:` in `editor.rs`, `block_range`) | `Ctrl+V` blocks are in screen columns, but a tab (or wide char) only partly inside the block is deleted, yanked or changed whole; vim splits a tab into spaces | Split the tab into spaces at the edges |
| Tree-sitter costs grow with the text (`shortcut:` in `editor/syntax.rs`) | Parsing runs on the main thread without a timeout (the first parse of a huge file blocks); lines over 8 KiB and visible text past 256 KiB are not highlighted; `:compact` forces a full reparse; objects scan the whole tree. A layer touched by an edit is parsed again whole, `injection.combined` ones rebuild all layers (13 ms at 80 KB of JavaScript), and injections stop above 1 MiB of text; locals are queried again for the nodes an edit changed (1 ms after an edit in a 100 KB Rust file; a single node over 4 KiB with no children to split, or the first resolution, costs its whole text) and stop past 1 MiB. The incremental parse of a layer is not used for layers under 2 KiB nor for `markdown_inline`; `locals.scm` ignores `local.scope-inherits` (scopes always inherit) | A parse thread on a `Text` snapshot (as `:w`); a variable-length chunking that follows scopes |
| Filetype detection is by name only (`shortcut:` in `editor/filetype.rs`) | No shebang or content sniffing: an extensionless script has no filetype until `:set ft=` | Look at the first line |
| Background detection | Needs a terminal answering OSC 11; others (and errors, timeouts up to 1 s at startup) fall back to dark | `:set bg=light` |

## Verified properties

Correctness of the library is backed by differential tests against `String`, invariant checks on every produced tree, persistence checks on old versions, Miri on the `unsafe` chunk code (including concurrent appends), and 100% line/function/branch coverage. Performance numbers are in [../guides/benchmarks.md](../guides/benchmarks.md). See [../guides/testing.md](../guides/testing.md).
| Messages taller than the screen show their last rows (`editor/render.rs`) | No `:more` paging | A pager for long output, a timer in the event loop |
