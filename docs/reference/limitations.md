# Limitations and roadmap

## Library

| Limit | Impact | Upgrade path |
|---|---|---|
| In-place edits need an unshared version | `Text::insert_mut` / `delete_mut` and `Document` inside a group update nodes in place (typing 13 ns per key, paste 330 ns, backspace 20 ns); when each edit must stay a version (`Document` without a group, or a clone per edit) the path is copied: 50-60 ns per key, ~610 ns per paste | Nothing to do: a kept version needs its own path. Ranges that span pieces, and whole-piece deletes, are always persistent (`split` + `join2`) |
| Pieces still multiply under scattered edits | Extension only helps contiguous typing; random edits still add pieces (~3000 after 2000 random edits) until `Text::compact`/`Document::compact` runs (the editor does it on idle past `compactat` pieces) | Compaction is explicit: the library never compacts on its own |
| Chunks stay alive while referenced | A chunk whose text is mostly deleted is kept whole by the remaining pieces, and by every version in the undo history, also after `compact` | `Document::drop_history_before` frees what only older versions use |
| `memory_bytes` is approximate | Counts chunk buffers at capacity and nodes, not allocator overhead or `Arc` headers; shared structure is counted in every version | Good enough for `:stats`; exact accounting would need allocator hooks |
| Add chunk allocated in full | Up to 64 KiB bytes + 64 KiB newline slots reserved per add chunk (untouched pages are usually not committed by the OS) | Smaller maximum, or a separate growable newline area |
| `Chunks` allocates its path per call (`shortcut:` in `text.rs`) | One `Vec` allocation per `chunks()` walk; `ChunksIn` keeps its path inline | Convert `Chunks` to the inline path when a benchmark of short `chunks()` walks shows it (a hot path: needs the comparison tables rerun) |
| Mixed line endings normalized to one | Saving rewrites the other endings | Track original endings per line if fidelity is ever required |
| Chunk ≤ 4 GiB (`u32`) | Files over 4 GiB cannot load (one exact chunk) | Split large loads into several exact chunks |
| `rfind_before` worst case O(n log n) | Backward search with few matches and none after the cursor rescans doubling windows to the start | A reverse regex engine, or an index of match starts |
| Char conversions scan | Per-line ones are O(line length), global ones (`char_count`, `offset_to_char`, `char_to_offset`) O(n), measured 0.008-0.034 ns/B (0.4-1.7 ms for 50 MB, SIMD counting from `str_indices`); on a 1 MB single line every column conversion scans the line | A char index per sealed chunk built lazily on the first char query (see D15) |
| Newline scan is SIMD only on aarch64 and x86_64 | NEON and SSE2 `mask64` (~0.1 ns/B on the M1, ~0.26 on an i5-8365U, Rust sources); every other architecture (wasm32, 32-bit x86, loongarch64, s390x, riscv64, powerpc64) uses the portable SWAR mask (~0.13 ns/B on the M1). On x86_64, AVX2 and SSE4.2 were tried and lost; AVX-512BW is not worth trying | One `mask64` per architecture where it beats SWAR, in the order and with the `std::arch` status and test needs listed in D16 (wasm32 simd128 and 32-bit x86 first: stable intrinsics), or `std::simd` once stable; same A/B acceptance as D16 |
| History is never freed | Every version (and the chunks it references) lives until the `Document` is dropped | Drop versions older than a seq or a time |
| Atomic refcount traffic | Path copies clone sibling and chunk `Arc`s; drop of old versions dominates benchmarks that discard every version | Non-atomic `Rc` would lose `Send + Sync` snapshots; batch edits (one version per group) if needed |
| Recursion in `join`/`split` | Depth O(log n), not an issue in practice | — |

## Editor

| Limit | Impact | Upgrade path |
|---|---|---|
| Huge lines are not free (`editor/layout.rs`, `editor/render.rs`, `editor/search.rs`) | Typing, motions, objects and scrolling in a line of millions of chars cost the window around the cursor (see `rim.md`, Huge lines). Still O(line): the first jump deep into a line (2.1 M chars of CJK: about 5 ms to build its cluster index and lay out its prefix once, ASCII 1 ms), `gk`/`k` into a huge line above (it is laid out whole, then kept), a failed `ci(`-style search (scans back to the text start), sentence objects, `yy`/`p`, and a text change on a visible huge line with `hlsearch` (the regex runs from the line start so matches stay exactly vim's: 100 000 matches about 7 ms, none about 0.2 ms) | Checkpoints of the row layout and of the match state per line |
| Save via temp file + rename | Permissions are copied and symlinks followed, but hard links are broken, owner is kept only when allowed (root or same user), ACLs and xattrs are lost | Write in place after a backup |
| `:highlight` is a subset of vim's (`editor/highlight.rs`) | Color names are the 16 of vim plus a few X11 ones (`NAMES`, not all of rgb.txt), no `fg`/`bg` as a color, `guisp` is checked but not drawn, no `font`, `blend`, `start`/`stop`; `:hi` lists only the user's groups; `:set bg=` keeps the user's groups (vim reloads the colorscheme); with `termguicolors` a missing `gui*` key falls back to its `cterm*` value, which vim does not; groups are global, not per buffer | The rest of rgb.txt, undercurl colors and a pager for the listing on demand |
| Vim subset only | No vim regex syntax (Rust `regex` only), uppercase (file) marks, `-` small-delete register, block `O`, multi-cursor | Add on demand |
| Tag objects scan the whole text (`shortcut:` in `editor/objects.rs`) | `it`/`at` slice and scan the text on every use | Scan outward from the cursor |
| The system clipboard is read only through OSC 52 | `"+p`, `Ctrl+R +` and `@+` send an OSC 52 query and wait up to 500 ms for the answer; a terminal that does not answer it (or has clipboard reads disabled) gets `Clipboard read failed`, with no fallback | None planned: terminals without OSC 52 reads are unsupported |
| `:p` shows one line (`shortcut:` in `editor/ex.rs`) | `:p` and `:g/pat/` show only the last line printed (one message row) | A message pager |
| Ex corner cases (`shortcut:` in `editor/ex.rs`, `editor.rs`) |  `:put :` and the register `:` know typed lines only; `:r !cmd` is missing; the `c` flag of `:s` is refused under `:g`/`:normal`; `:r` copies the file into the text; with `F` taken out of `'shortmess'` the file info of `:e` is rim's own text at once, where Neovim shows `"file" 3L, 4B` again after the redraw (`need_fileinfo`); `'binary'` does not keep `\r` (loading normalizes the text) and the options Neovim resets with it that rim does not have (`textwidth`, `wrapmargin`) are left out | Marks that follow lines; a confirm loop that waits; `Text::append_text` |
| Insert mode `'smarttab'`/`'softtabstop'` Backspace and Tab take a run of typed printable chars as one only from the typeahead (`:normal`, macros, `.`) | `inserted_space` (a space just typed: Backspace deletes it alone) is set for the first char of such a run only, as Neovim's `insertchar` takes the run at once; typed one key at a time every space sets it | None: it is Neovim's behavior |
| Tree-sitter costs grow with the text (`shortcut:` in `editor/syntax.rs`) | Parsing runs on the main thread without a timeout (the first parse of a huge file blocks); lines over 8 KiB and visible text past 256 KiB are not highlighted; `:compact` forces a full reparse; objects scan the whole tree. A layer touched by an edit is parsed again whole, `injection.combined` ones rebuild all layers (13 ms at 80 KB of JavaScript), and injections stop above 1 MiB of text; locals are queried again for the nodes an edit changed (1 ms after an edit in a 100 KB Rust file; a single node over 4 KiB with no children to split, or the first resolution, costs its whole text) and stop past 1 MiB. The incremental parse of a layer is not used for layers under 2 KiB nor for `markdown_inline`; `locals.scm` ignores `local.scope-inherits` (scopes always inherit) | A parse thread on a `Text` snapshot (as `:w`); a variable-length chunking that follows scopes |
| Filetype detection is by name only (`shortcut:` in `editor/filetype.rs`) | No shebang or content sniffing: an extensionless script has no filetype until `:set ft=` | Look at the first line |
| Background detection | Needs a terminal answering OSC 11; others (and errors, timeouts up to 1 s at startup) fall back to dark | `:set bg=light` |
| `3iab<Down>` lands on the column where Insert began (Neovim, with keys pending) | With a count and the keys in the typeahead Neovim does not update `curswant` while typing; rim goes to the cursor's column (`insarrow.typed.vim`, 4 known cases) | Port where `curswant` is taken in `edit()` |
| Word classes: `'iskeyword'` is the default, emoji data is newer than Neovim's (`editor/wordclass.rs`) | `:set iskeyword` does nothing; the emoji of a newer Unicode than Neovim's `utf8proc` (U+1FA7D.., the reserved U+1FC00 block) are class 3 here and 2 there; `*` over words of mixed classes searches with Rust's `\b` | An `'iskeyword'` option; a Unicode table of Neovim's version |
| Vimscript is partial and being made identical to Neovim's (`editor/script.rs`, `editor/script/`; phases in [vimscript.md](vimscript.md)) | User functions, Funcrefs, exceptions (`:try`, `:throw`) work (`:function`, `:call`, `:return`, `a:`/`l:`, `function()`, `funcref()`, `call()`) lambdas, closures and Dictionary functions too; an empty buffer is one with a single empty line for `:append`/`:insert`/`:change` (`shortcut:` in `editor/script/append.rs`); `:source!`, `:filter`; most of vim's function library is missing (about 90 builtins) (see [vimscript.md](vimscript.md)); `:redir @r` writes the register when the redirection ends (Neovim, with every message) and `:redir > file` takes the first file name only; the question "OK to swap" of a backwards range is not asked inside a block, `:normal` or `:execute` (rim swaps); `shortmess` flags other than `a`, `t`, `T` do nothing; `exists('#Event')` is always 0 and `exists('##Event')` only knows the event names (no autocommands; `shortcut:` in `editor/script.rs`); `sort()` compares in the order of macOS's `qsort`, so a failing comparison reports as often as there (glibc's differs; `shortcut:` in `editor/script/funcs.rs`); `printf('%p', x)` reads `x` as a number (Neovim prints the address of the container); no `Ctrl+R =` history popup, `=` has no completion | Phase E of vimscript.md |

| `RcString` differs from `String` where the layout forces it (`rc.rs`) | `Rc<str>` is built by casting the pointer of a `RcBox<[u8]>` to a `RcBox<str>`; `RcString` has the full stable API of `String` (1.100) and the stable trait impls, except: the methods that take or return a `Vec<u8>` (`from_utf8`, `from_utf8_lossy_owned`, `from_utf8_unchecked`, `TryFrom<Vec<u8>>`) and `into_bytes`/`into_boxed_str` copy (the lossy ones decode straight into the buffer, and `Rc::<str>::from_utf8_lossy` decodes bytes into an `Rc<str>` with one allocation), because a `Vec` buffer has no room for the strong count and is not adopted; `into_raw_parts`/`from_raw_parts` use this type's own box (the pointer is the text, the header sits in front), and `leak` cannot be reversed; `try_reserve`/`try_reserve_exact` and `from_utf8`/`from_utf16` return this module's `TryReserveError`/`FromUtf8Error`/`FromUtf16Error` (std's fields are private); `Drain` copies the drained text out and is an iterator over it; the unstable `String` items (`try_with_capacity`, `remove_matches`, `replace_first`, `replace_last`, `into_chars`, the `ascii::Char` impls) are not ported | Nothing planned; script strings (`RcStr`) already use `rc::Rc<str>` and build with `RcString`/`rc::format` |

| Undo is Neovim's `undo.c` (`editor/undo.rs`), with limits (`shortcut:` in `editor/undo.rs`, `editor.rs`) | `UH_CHANGED`, `'modified'`, `file_ff_differs` (without `'endoffile'`, `'bomb'`, `'fileencoding'`, which rim lacks) and `'undoreload'` are Neovim's; `:s` saves the half-changed line. `U` is `u_undoline` (`ULine`, `u_saveline` in `u_save`, `u_clearline` at `open_line`, `dd`, `2cc`, `:m`, `:t`, `:retab`, `:r`, `:e!`); freed headers let go of their `Document` versions (`trim_history`) | The flags and the half-changed line on demand |
| Marks follow Neovim's `mark_adjust` by the shape of the edit | A mark, a jump list entry, a change list entry, the last Visual area (`last_visual`, which is `b_visual`) and the cursor of another window are a line and a byte column (`Mark`); `adjust_marks` (`changemarks.rs`) derives what Neovim's `mark_adjust`/`mark_col_adjust` calls do from the edits of a command (whole lines deleted or added, `do_join`, `op_delete` over lines, a line split: no column move, `OPENLINE_MARKFIX` is only for `'textwidth'`, which rim does not have), and `:m`, `:sort`, `cc`/`cj`, `:s` over lines and the undo regions call `mark_adjust` themselves. Where a command is not told apart by the shape of its edit, a hint field says it (`marks_split`, `marks_below`, `marks_manual`). The change list follows each edit and each `set_dot` (`changed_common` runs once per `changed_lines`; `J` makes its two calls); `marks_chardel` tells a charwise `op_delete` over line breaks (the marks of the first line stay, `do_join` moves the last line's) from a linewise one. Left: `Buffer.last` (the cursor of a buffer nobody shows) is still a byte offset; a charwise delete from column 0 of the first line to the end of the buffer outside `op_delete` (`vGd` is `op_delete`, so it is right; `:s` or another command with that shape of edit is read as whole lines) | The marks of `u_undoredo` over freed headers |
| Buffers and windows are Neovim's `do_buffer_ext`/`close_buffer`/`win_close` (`shortcut:` in `editor/buffers.rs`, `editor/ex.rs`, `editor/windows.rs`, `editor/bufdel.rs`) | no terminal, `help`, `quickfix`, `prompt` or `acwrite` buffers (`'buftype'` knows `nofile` only); `++ff`, `++enc`, `++bin`, `++bad`, `++p` are parsed and checked but do not change how a file is read or written; one argument list, not one per window (`:arglocal`); `:cd` has no `cdpath` and no window-local directories; a directory cannot be edited | `:arglocal`, `'cdpath'` |
| `=`, `gq`, `g?` and Visual `p` with an empty register (`editor.rs`, `editor/parse.rs`) | the operators `=` (needs the cindent engine of `indent_c.c`, 4008 lines, and 'cindent'/'indentexpr'/'equalprg'), `gq` (`format_lines`: 'textwidth', 'formatoptions', 'comments', 'formatlistpat', 'formatprg' are not options of rim), `g?` (rot13) are not keys; Visual `p` finds the register empty before it deletes the selection (Neovim deletes first); `b:changedtick` is checked over 598 cases that leave these out | Port `indent_c.c`, `textformat.c` |
| `w_wcol`/`w_wrow` (`winnr('j')`...) are Neovim's (`curs_columns`, `scroll_to_fraction`) but for a cursor on a wrapped line that is taller than the rows left of its window, in a window that was just split or resized (`editor/windows.rs`) | 31 of 936 recorded sequences differ by one row (the line is shown from `w_skipcol` in Neovim); the others match | Port `w_skipcol` of `curs_columns` and `update_topline` |
| File name arguments are expanded as Neovim does (`script/expand.rs`, `script/evalvars.rs`) | `ExpandOne` runs `$SHELL -c` for `{}` and backticks like `os_expand_wildcards`; `'isfname'` is a table of its own for `<cfile>` and completion only (`init_chartab` is not ported); `expand_env` takes the `esc` flag as a shortcut | Port `init_chartab` |
| Every key is followed by a full repaint (`main.rs` loop, `editor/render.rs` `render`/`draw`) | `editor.render()` runs before each event and `draw` rewrites every row (`MoveTo`, `Clear`, attributes, spans) with no diff against the previous frame. Measured in a pty on a 40x120 screen: about 4.2 KB per key, 600 keys typed in one burst (a paste) write 2.5 MB, and in one long line the frame grows with the line, so the cost is quadratic (200, 600, 1000 chars in one burst: 0.3, 3.3, 8.5 s; Neovim: 5 ms for 2000). Bracketed paste (`?2004h`) is not enabled either | Skip `render` while `event::poll(0)` has more events (one repaint per burst); then diff rows against the previous frame |
| Long lines are read with `slice` (`editor/render.rs`, `Text::line`) | A line that spans pieces is copied whole, though a few hundred columns are on screen | Read only the visible bytes with `Text::chunks_in` |
| Windows of 256 bytes cut with `slice` (`editor.rs` `first_non_blank` and `cluster_at`, `editor/syntax.rs` `with_comma`) | A loop of `slice` calls instead of one walk | Walk the line with `Text::chunks_in` |
| The frame reads each visible line with `Text::line` (`editor/render.rs` `with_rows`, `height_to`; `editor/syntax.rs` highlighting) | One tree descent per line, about 50 per frame (a few microseconds against ~44 us for a Normal frame) | `Text::lines_in` over the visible range, one descent; needs the per-line layout cache reorganized, so only if a profile shows it |
| The search region is copied whole (`editor/search.rs` `region`) | `slice` of every line the matches cover, to count columns | Count the columns piece by piece over `Text::chunks_in` |

## Verified properties

Correctness of the library is backed by differential tests against `String`, invariant checks on every produced tree, persistence checks on old versions, Miri on the `unsafe` chunk code (including concurrent appends), and 100% line/function/branch coverage. Performance numbers are in [../guides/benchmarks.md](../guides/benchmarks.md). See [../guides/testing.md](../guides/testing.md).
